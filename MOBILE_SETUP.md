# ESUG 2027 — Ember + Capacitor mobile app

Ember app (`ember-cli` + Vite) wrapped with Capacitor for iOS and Android.
App ID: `org.esug.app2027`.

## Prerequisites

- Node.js >= 20.19
- For iOS builds: a Mac with Xcode + CocoaPods (`sudo gem install cocoapods`)
- For Android builds: Android Studio + an installed SDK/emulator

## First-time setup

```bash
npm install
```

## Day-to-day web development

```bash
npm start        # runs the Ember dev server at http://localhost:4200
npm run lint
npm test
```

## Building for iOS / Android

Capacitor serves the _built_ Ember app (`dist/`), not the dev server, so any
time you change app code you need to rebuild and re-sync before testing on
device/simulator:

```bash
npm run cap:sync     # ember/vite build -> npx cap sync (copies dist into ios/ and android/)
npm run cap:ios       # sync + open the Xcode project
npm run cap:android   # sync + open the Android Studio project
```

From Xcode or Android Studio you run/debug on a simulator, emulator, or a
connected device as normal.

## Live reload on device (optional)

For faster iteration, point Capacitor at the running Ember dev server instead
of the static build, by temporarily adding to `capacitor.config.js`:

```js
server: {
  url: 'http://<your-machine-ip>:4200',
  cleartext: true,
}
```

Remove this before shipping a build — production builds must serve the
bundled `dist/` assets, not a dev server URL.

## Project layout

- `app/`, `config/`, `tests/` — standard Ember app
- `capacitor.config.js` — Capacitor config (app id, name, web dir)
- `ios/` — generated Xcode project (native shell)
- `android/` — generated Android Studio/Gradle project (native shell)

`ios/` and `android/` are checked in (they're where you add platform-specific
config, icons, splash screens, and native plugins), but their build
artifacts (Pods, Gradle caches, `public/` webview assets) are gitignored
since they're regenerated by `cap sync`.

## Adding native functionality

Capacitor plugins (camera, push notifications, geolocation, filesystem,
etc.) are npm packages, e.g.:

```bash
npm install @capacitor/push-notifications
npx cap sync
```

See https://capacitorjs.com/docs/apis for the plugin catalog.

## App icon

`resources/icon.png` is the source icon (the ESUG 2027 logo flattened onto
its own navy background — app icons can't have transparency). To regenerate
the native icon sets after changing it:

```bash
npm install
npm run generate:icons
```

This uses [`@capacitor/assets`](https://github.com/ionic-team/capacitor-assets)
to regenerate `ios/App/App/Assets.xcassets/AppIcon.appiconset` (and, once you
add the Android platform, its icon set too). Re-run `npm run cap:sync` /
rebuild in Xcode afterwards to see the change on device.

The browser favicon and "Add to Home Screen" icon (`public/favicon.png`,
`public/apple-touch-icon.png`) are generated from the same source but aren't
covered by that script — regenerate them manually if the logo changes.

## Launch screen

The iOS launch screen (`ios/App/App/Base.lproj/LaunchScreen.storyboard`) is
deliberately lightweight: a plain `#f5f7fa` background with the balloon,
340×340 points, centred (1020 px on a 3× iPhone, about the 1024 px of the
app icon). The balloon is the `SplashLogo` image set
(`ios/App/App/Assets.xcassets/SplashLogo.imageset`, 340/680/1020 px), made
from `resources/splash-logo.png`: `resources/icon.png` with its white
background made transparent. It is maintained by hand, not by
`generate:icons`.

iOS only shows the launch screen while the app process starts, which is
much shorter than the time the first page takes to load, and the web view's
own background colour would cover anything behind it. So
`MainViewController.swift` lays an identical view (the same `SplashLogo`
balloon, size and position, on `#f5f7fa`) on top of the web view, and fades
it out once the first page has loaded (`isLoading` turns false), or after 5
seconds at the latest.

The launch screen used to show the full-screen 2732×2732 `Splash` image that
`generate:icons` makes. With that image, iOS showed a black screen for
about half a second before the launch screen appeared, most likely because
iOS draws launch screens with very little memory and the image takes about
30 MB once decoded. `generate:icons` still writes
`Splash.imageset` (from `resources/splash.png` and
`resources/splash-dark.png`), but nothing uses it any more.

The app has no dark theme, so `Info.plist` sets `UIUserInterfaceStyle` to
`Light`.

## No black screen at launch

Capacitor makes the web view transparent until the first page has loaded.
To avoid a black flash in between the launch screen and the home page, the
window behind it (`SceneDelegate.swift`), the web view (`backgroundColor` in
`capacitor.config.js`) and the launch screen all use the page background,
`#f5f7fa` (`--esug-bg` in `app/styles/app.css`). Keep the four in step if
the page background ever changes.

The scene configuration in `Info.plist` has no `UISceneStoryboardFile`:
with one, iOS first builds a window from `Main.storyboard` (with its own,
colourless, loading web view) before `SceneDelegate.swift` replaces it with
the window it builds in code, which caused a black flash at launch.

## iOS swipe-back gesture

`ios/App/App/MainViewController.swift` subclasses Capacitor's bridge view
controller solely to turn on `webView.allowsBackForwardNavigationGestures`,
which enables the native edge-swipe-to-go-back gesture. This only works
because the Ember router uses real `history.pushState` navigation
(`location = 'history'` in `app/router.js`), so the webview builds up an
actual back/forward list for the system gesture to use.

This app's actual launch path is `SceneDelegate.swift`, which builds the
window and root view controller directly in code rather than loading
`Main.storyboard` — so `SceneDelegate.swift` is what instantiates
`MainViewController()`. (`Main.storyboard`'s `customClass` is also set to
`MainViewController` for consistency, but since the storyboard is never
actually loaded, it's not what makes this work.)

## Android back button and back gesture

`app/instance-initializers/android-back-button.js` handles Android's system
back action (the back button, or the edge-swipe back gesture with gesture
navigation; both arrive as the same `@capacitor/app` `backButton` event): on
the home page it sends the app to the background, elsewhere it goes back to
the previously visited page. Like the iOS swipe-back gesture, this relies on
the Ember router's real `history.pushState` navigation.
